## Задание 1

**Опишите основные преимущества использования масштабирования методами:**

### 1. Активный master-сервер и пассивный репликационный slave-сервер
Данная топология (Active-Passive) в первую очередь нацелена на **отказоустойчивость (High Availability)** и безопасность данных, а не на резкое увеличение производительности.
* **Быстрое восстановление после сбоев (Failover):** В случае выхода из строя основного master-сервера, пассивный slave может быть быстро повышен до роли master, что минимизирует время простоя (downtime) системы.
* **Безопасное резервное копирование:** Бэкапы можно снимать с пассивного slave-сервера. Это полностью исключает блокировки таблиц и нагрузку на дисковую подсистему во время бэкапа, не влияя на производительность основного master-сервера, обрабатывающего запросы клиентов.
* **Тестирование и отладка:** На пассивном сервере можно безопасно тестировать новые версии ПО, схемы данных или проводить анализ данных без риска для продакшена.

### 2. Master-сервер и несколько slave-серверов
Данная топология (Active-Read Replicas) добавляет к преимуществам отказоустойчивости возможность **горизонтального масштабирования операций чтения**.
* **Масштабируемость чтения (Read Scalability):** Все запросы на изменение данных (INSERT, UPDATE, DELETE) идут на master, а тяжелые или массовые запросы на чтение (SELECT) распределяются между несколькими slave-серверами через балансировщик нагрузки. Это кратно увеличивает общую пропускную способность системы.
* **Географическое распределение:** Slave-серверы можно разместить в разных дата-центрах или регионах мира. Это позволяет пользователям обращаться к ближайшему к ним серверу, значительно снижая сетевую задержку (latency).
* **Разделение нагрузок по типам задач:** Можно выделить отдельные slave-серверы под специфичные задачи: один для API мобильного приложения, другой для генерации тяжелых аналитических отчетов, третий для полнотекстового поиска. Это изолирует проблемы и предотвращает взаимное влияние нагрузок.

## Задание 2

**План выполнения горизонтального и вертикального шардинга базы данных (таблицы: пользователи, книги, магазины).**

### Принципы построения системы и разграничения данных

1. **Вертикальное масштабирование (секционирование):** 
   Мы разделим единую базу данных на три логические базы данных, исходя из предметной области и паттернов доступа. Это уменьшит размер каждой отдельной БД, позволит хранить их на разных физических серверах и использовать разные типы движков или настроек под конкретную задачу.
   * **БД `Users_DB`:** Хранит таблицу `пользователи` (id, имя, email, хэш пароля, настройки). Высокая частота операций аутентификации и обновления профилей.
   * **БД `Catalog_DB`:** Хранит таблицу `книги` (id, название, автор, isbn, подробное описание). Характеризуется большим объемом текстовых данных, редкими изменениями и очень частым чтением.
   * **БД `Stores_DB`:** Хранит таблицу `магазины` (id, название, адрес, регион, контакты) и связующие таблицы (например, наличие книг в конкретных магазинах).

2. **Горизонтальное масштабирование (шардинг):**
   Внутри каждой вертикальной БД мы применим шардирование для распределения нагрузки.
   * **Шардирование `пользователей`:** По хэшу `user_id` (например, `hash(user_id) % N`). Это обеспечивает равномерное распределение пользователей по шардам и быстрый поиск по первичному ключу.
   * **Шардирование `книг`:** По диапазонам `book_id` или по хэшу `category_id` (жанру). Это позволяет кэшировать и читать целые категории книг с одного шарда.
   * **Шардирование `магазинов`:** По географическому признаку (региону/стране). Например, Шард 1: "Москва и ЦФО", Шард 2: "Санкт-Петербург и СЗФО". Это удобно для бизнес-логики и аналитики.
